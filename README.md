## 🌌 Overview

The **NTE Ascendancy Toolkit** is an independent, community-driven companion environment for *Neverness to Everness* (NTE). Where the original game thrusts you into a reality-bending city of anomalies, spectral streets, and corporate intrigue, this toolkit stands beside you like a well-worn field journal — organized, annotated, and ruthlessly practical.

Think of it less as a "trainer" in the blunt sense, and more as an **orchestral conductor** for your play session. It doesn't shout; it tunes. It doesn't override; it harmonizes. Every module in this project is designed around a single philosophy: **the player should spend more time immersed in the world and less time fighting the interface.**

Whether you are a lore archivist cataloguing every anomalous event, a build-crafter chasing the perfect resonance curve, or a casual wanderer who simply wants the UI to stop elbowing them in the ribs — the Ascendancy Toolkit has a seat reserved for you.

## ✨ Why This Project Exists

Most companion utilities are born from frustration. Ours was born from **curiosity**.

When *Neverness to Everness* first introduced its layered anomaly system, players discovered that the game's pace rewards observation — but the surrounding tooling ecosystem was stuck in a pre-observation mindset. Menus lagged. Overlays collided. Stat readouts arrived three seconds after the moment that mattered. It felt like reading a mystery novel where the pages turn themselves.

The Ascendancy Toolkit was created to restore **narrative rhythm**. Instead of stuffing more numbers onto the screen, we asked a different question:

> *"What would a companion look like if it respected your attention as much as the game does?"*

The answer became this repository — a modular, localization-first, accessibility-conscious suite that treats your screen real estate as sacred ground and your curiosity as the north star.

## 🎨 Responsive UI Philosophy

Responsiveness, in our vocabulary, is not merely "does it fit on a phone." It is a **conversation**.

The interface recalculates its density based on:

- **Viewport geometry** — from ultrawide battlestations to handheld companions.
- **Input modality** — touch, pointer, or hybrid.
- **Ambient lighting context** — a dim-room theme whispers; a bright-room theme speaks clearly.
- **Session fatigue heuristics** — optional, and fully local. After a long session, controls gently enlarge rather than adding popups.

We borrow a metaphor from architecture: a well-designed room doesn't tell you where to stand. It offers **alcoves**. The Ascendancy Toolkit offers alcoves.

## 🕰️ 24/7 Guidance Desk 🛎️

Software that touches your leisure time should be reachable when leisure happens — which is rarely during business hours.

The Guidance Desk is a **round-the-clock support posture** composed of:

1. **Pinned FAQ threads** curated by maintainers and refreshed weekly.
2. **Community triage rotation** — volunteers across time zones, so no question waits until "morning."
3. **Async walkthroughs** with annotated screenshots for every major module.
4. **Escalation ladders** that convert recurring questions into permanent documentation improvements.

We don't promise instant answers. We promise **visible momentum** on every open question.

## 🧠 Cognitive Load Mapping

An underrated feature of any companion tool is its ability to *disappear*. The Ascendancy Toolkit includes a **Cognitive Load Map** — a diagnostic view that shows, over the course of a session, how much of your attention each module consumed.

The goal is not to maximize engagement. It is to **minimize friction per unit of delight**. If a module trends toward noise, we tune it down in the next release. If a module trends toward silence when you needed it, we tune it up.

This is a rare case where the software grades itself.

## 🛰️ Telemetry & Privacy Posture

**Local-first, always.** Every ledger, note, and tuning profile lives on your machine unless you explicitly export it. There is no silent upload, no shadow analytics pipeline, and no "improve our service" checkbox buried in a submenu.

The only network activity the toolkit performs by default is checking for **release notes** so you know when something new arrives. That check is a plain, cacheable request and can be disabled with a single toggle.

## ⚙️ Configuration Atlas

Everything tunable lives in a human-readable configuration file with inline comments. There is no proprietary binary blob guarding your preferences.

Highlights:

- **Theme presets** — Dawn, Dusk, Neon, Monochrome, and a "Match the Game" auto-mode.
- **Hotkey rebinding** — every action, no exceptions.
- **Module isolation** — run one module, run all of them, or run none.
- **Notification verbosity** — from "chatty" to "monastic silence."

A companion document, `CONFIG_ATLAS.md`, explains every key with examples. No guessing.

## 🧪 Quality & Testing Discipline

We believe that reliability is a form of **respect**. Every release passes through:

- Deterministic build pipelines so the artifact you receive matches the source you can read.
- Cross-platform smoke suites covering the major desktop environments.
- Golden-path playthrough simulations for each module.
- A manual "first hour" checklist, because automated tests cannot feel frustration.

Bugs are tracked in the open. Fixes are announced in the same channel as the bug report, so nobody has to wonder whether their voice was heard.
